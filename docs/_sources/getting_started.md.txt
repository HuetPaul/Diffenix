# Getting started

## Installation

You can install this library directly with pip:
`pip install phenigraph`

Alternatively, you can download it from GitLab, after which you will need to compile it.
In the main folder, run the following command :

`python setup.py bdist_wheel`

The installation wheel file will be in the newly created ‘dist’ folder.
To install the library in the local environment, use the following command:

`pip install /path/to/wheelfile.whl`

### Directory and data needed before starting

The library assumes that the working directory has a specific structure. You can change the reference directory and the location of necessary data files by creating a `paths.txt` file in the working directory.

The necessary data are:
- The water cross-section which can be found on this [page](https://home.strw.leidenuniv.nl/~ewine/photo/display_h2o_b89e91ccf14bfd7f485dd7be7d789b0a.html):
        The file should be saved as `H2O.txt` in a directory called `Leiden_database`. 
        The name and the location of this directory can be changed in the `paths.txt` file.

- The interstellar spectrum which can be found at this [page](https://home.strw.leidenuniv.nl/~ewine/photo/radiation_fields.html).
        The file should be saved as `ISRF.dat` in the `Leiden_database` directory
        Several radiations files are available on this page, the standard ISRF works fine for most cases.

- The luminosity data. These data are much more difficult to obtain since they must be produced by Stellar simulation codes such as [cesam2k20](https://www.ias.u-psud.fr/cesam2k20/). The structure of this file will be described in a dedicated section. Without such files, the luminosity will be assumed to be a constant `Ls` that can be set in a configuration dictionary (see later) and the water photodissociation due to the central star will not be modelled.

#### The directory structure :

The main directory referred to as `racine` in the paths file is assumed to be the current working directory.
It is assumed that this main file contains a directory named 'Leiden_database', which contains the 'H2O.txt' and 'ISRF.dat' files.
If the user has data modelling the central star, it is assumed to be in a 'data_star' directory inside the main
`racine` directory, in a .npz file called `data_fus.npz`.
Finally, a 'Results' directory is needed to save the Sol objects.

#### The paths.txt file

If you don't want to work inside the 'racine' directory or want the data to be organised differently, you can write a 'paths.txt' file.
This file is structured as follows:
One line stands for one directory.
Each line starts with the name of the directory to be relocated; this can be 'racine', 'Results', 'data_leiden' or 'data_stars'.
Then a comma separates this name from the path to the new directory.

Example: Reproduce the default structure.

```
racine,.
results,./Results
data_leiden,./Leiden_database
data_stars,./data_stars/data_fus.npz
```

## A first example

In the following sections, we will assume that these libraries are imported with the following names:

```
import numpy as np
from scipy.integrate import cumulative_trapezoid
import phenigraph as g  # To generate plots
from diffenix import time_integration as ti # Only the time_integration submodule is nedded for the user
```

All the information that characterises the system to be modelled, as well as information on the models used and numerical settings,
should be included in a single dictionary. Examples of such dictionaries are included with the library and can be modified to fit the user's needs.

### Integration in time

Then let's start our first simulation!

```
sol: ti.Sol = ti.time_integration(tf= ti.Myr, save_time_step=0.1*ti.Myr,consts_params=configs)
```

The evolution of the disc is modelled from an initial time of zero to a final time of one million years, t_f.
The initial time is defined as the point at which the protoplanetary disc dissipates.
This can be set relative to the star's lifetime in the configuration dictionary via the "t0" parameter.
This is only useful where luminosity data are provided for the central star.

The result is saved in a dedicated Sol object, sol.
If the integration stops before the end of the integration time tf, the data will not be lost.
This object is automatically saved to the 'Results' directory at each 0.1 Myr time step.
As there is no `Simulation` entry in the configuration dictionary, the simulation's name is generated
automatically and is displayed when the integration begins.
If the code is run for the first time, it should be 'Simulation_1'. The number will then increase for each new simulation.
A new directory with the name of the simulation should have been created inside the 'Results' directory.
The .npz file containing the Sol object is located inside this directory and is named Simulation_diffusion.npz.

To reload this simulation, follow these steps:

```
sol = ti.Sol(filename="Simulation_diffusion", directory=ti.results+"/Simulation_1")
```

## An asteroid belt with a constant gas mass generation rate

The previous simulation was initialised with a given mass of hydrogen and no further mass was produced. There was also only one molecular species.
However, this code can model the evolution of multiple chemical species, from their production at the asteroid belt to their photodissociation.
Let's start with a simple case involving a constant gas production rate at the asteroid belt level, using the same system as before.
After the evolution of the total surface density, the evolution of the mass fraction of each chemical species is integrated and saved at different times.
To avoid divergence in the numerical integration of this second set of equations, it is recommended that the simulation is initialised with a small amount of water.
This is controlled by the 'AB_mdot_st_init' parameter in the configuration dictionary.
The system is initialised with a steady-state water gas disc and a gas generation rate of AB_mdot_st_init.
In this simulation, there is no primordial hydrogen remaining.

```
configs=ti.sys_sol_ast.copy()
configs["AB_sublimation_model"] = "constant_rate"  
configs["AB_mdot_st_init"] = np.double(1e-10) * ti.Mearth / ti.Myr # setting the initial state

sol = ti.time_integration(tf= ti.Myr, save_time_step=0.1*ti.Myr, consts_params=configs)
```

## The thermal sublimations models

There are different models for the gas generation rate. There are two based on the gas sublimation by thermal heating.
The first and the simple one is referred in the configuration dictionary to be `"thermal_diff"`. 
This model assumes that the sublimation timescale and gas diffusion into the asteroid or KBO is negligible too.
It only evaluates the mass generation rate by the thermal diffusion timescale set by the thermal diffusion coefficient K
in the configuration dictionary (`AB_K` and `KB_K` for the asteroid belt and the Kuiper belt respectively)

Let model a young Kuiper belt similar to the one of [huet et al 2025](https://ui.adsabs.harvard.edu/abs/2025arXiv250603412H/abstract) :
In this simulation, only CO in produced at the Kuiper belt level

```
configs=ti.sys_sol_kuip.copy()
configs["KB_sublimation_model"] = "thermal_diff"  

sol = ti.time_integration(tf= 50 * ti.Myr, save_time_step=ti.Myr, consts_params=configs)
```

## The configuration dictionary

Here, we introduce each value needed to build the configuration dictionary. Best practice is to adapt one of the default configuration dictionaries, such as sys_sol_ast, sys_sol_ast_kuip or sys_sol_appd, to your needs, rather than rebuilding a new one from scratch.

- `racine` &rarr; the path to the racine directory
- `results`&rarr; the path to the subdirectory result
- `C_L`:  np.float64 &rarr; the length conversion unit (cannot be different of the global value (see the [Default unit system](#Default-unit-system) subsection to modify the global system of unit))
- `C_M`:  np.float64 &rarr; the mass conversion unit (cannot be different of the global value (see the [Default unit system](#Default-unit-system) subsection to modify the global system of unit))
- `C_t`:  np.float64 &rarr; the time conversion unit (cannot be different of the global value (see the [Default unit system](#Default-unit-system) subsection to modify the global system of unit))
- `Ms`: np.float64 &rarr; The central star's mass
- `Ts`: np.float64 &rarr; The central star's surface temperature (will be ignored if luminosity datas are provided)
- `Rs`: np.float64 &rarr; The central star's radius (will be ignored if luminosity datas are provided)
- `Ls`: np.float64 &rarr; The central star's luminosity (will be ignored if luminosity datas are provided)
- `a_in`: np.float64 &rarr; The inner boundary of the integration domain
- `a_out`: np.float64 &rarr; The outer boundary of the integration domain 
- `a0`: np.float64 &rarr; The radius used for the primordial hydrogen distribution (assumed to be the steady state centered on a0)
- `T0`: np.float64 &rarr; the temperature at a0 (will be ignored if luminosity datas are provided)
- `pls_temp`: np.float64 &rarr; the temperature radial power slope
- `mH_init`: np.float64 &rarr; The initial mass of primordial hydrogen
- `alpha`: np.float64 &rarr; The viscous parameter
- `gamma`: np.float64 &rarr; The adiabatic constant

- `AB_mdot_st_init`: np.float64 &rarr; The initial steady state mass generation rate for the asteroid belt 
- `AB_Mbelt`: np.float64 &rarr; The total asteroid belt's mass 
- `AB_Abelt`: np.float64 &rarr; The asteroids albedo
- `AB_a0`: np.float64 &rarr; The mean semi-major axis of the asteroid belt
- `AB_delta_r`: np.float64 &rarr; The half radial width of the asteroid belt (the belt extend from AB_a0 - AB_delta_r ti AB_a0 + AB_delta_r, be carful that the inner and outer bondary of the integration domain is smaller / larger than the inner / outer limit of the belt (i.e. a_in < AB_a0 - AB_delta_r and  AB_a0 + AB_delta_r < a_out). 
- `AB_K`: np.float64 &rarr; The thermal diffusivity in asteroids (dimension: $[L]^2 . [T]^{-1}$)
- `AB_Phi`: np.float64 &rarr; The asteroids porosity (no dimensions)
- `AB_rp`:  np.float64 &rarr; The pore's radius for asteroids
- `AB_f_ice`: np.float64 &rarr; The ice to refractory mass ratio for asteroids (no dimensions)
- `AB_rho_refr`: np.float64 &rarr; The density of refractory materials for asteroids (dimension: $[M] . [L]{-3}$)
- `AB_rho_ice`: np;float64 &rarr; The ice density for asteroids (dimension: $[M] . [L]{-3}$)
- `AB_sublimation_model`: str &rarr; The sublimation model, can be `none`, `constant_rate`, `thermal_diffusion` or `thermal_full` 
- `AB_const_mdot`: np.float64 &rarr; The mass generation rate for the`constant_rate` sublimation level 
- `AB_SD_amax`: np.float64 &rarr; The sizes used for the size distribution of asteroid belt (maximum size) 
- `AB_SD_abig`: np.float64 &rarr; The sizes used for the size distribution of asteroid belt 
- `AB_SD_amed`: np.float64 &rarr; The sizes used for the size distribution of asteroid belt 
- `AB_SD_amin`: np.float64 &rarr; The sizes used for the size distribution of asteroid belt (minimum size)
- `AB_SD_qh`: np.float64 &rarr; The power slope of size distribution between `AB_SD_amax` and `AB_SD_big`
- `AB_SD_qm`: np.float64 &rarr; The power slope of size distribution between `AB_SD_big` and `AB_SD_med`
- `AB_SD_ql`: np.float64 &rarr; The power slope of size distribution between `AB_SD_med` and `AB_SD_min`
- `AB_sb`: 
- `AB_e`: np.float64 &rarr; Asteroids mean eccentricity (used by the `collisions` sublimation model)
- `AB_i`: np.float64 &rarr; Asteroids mean inclination (used by the `collisions` sublimation model)
- `AB_As`: np.float64 &rarr; Asteroids minimum massic disruption energy (used by the `collisions` sublimation model) (dimension $[L]^2 . [T]^{-2}$), see [Löhne et al. 2008](https://ui.adsabs.harvard.edu/abs/2008ApJ...673.1123L/abstract) 
- `AB_bs`: np.float64 &rarr; Slope of asteroids massic disruption energy (used by the `collisions` sublimation model) (no dimension), see [Löhne et al. 2008](https://ui.adsabs.harvard.edu/abs/2008ApJ...673.1123L/abstract)
- `AB_bg`: np.float64 &rarr; Slope of asteroids massic disruption energy (used by the `collisions` sublimation model) (no dimension), see [Löhne et al. 2008](https://ui.adsabs.harvard.edu/abs/2008ApJ...673.1123L/abstract)
- `AB_t0_diss`: np.float64 &rarr; Asteroid belt lifetime before starting being disrupted
- `AB_t1_diss`: np.float64 &rarr; Asteroid belt disruption timescale

- `KB_mdot_st_init`: np float64 &rarr; The initial steady state mass generation rate for the Kuiper belt 
- `KB_Mbelt`: np.float64 &rarr; The total kuiper belt's mass 
- `KB_Abelt`: np.float64 &rarr; KBO's albedo (no dimension)
- `KB_a0`: np.float64 &rarr; The mean semi-major axis of the Kuiper belt
- `KB_delta_r`: np.float64 &rarr; The half radial width of the Kuiper belt (the belt extend from KB_a0 - KB_delta_r ti KB_a0 + KB_delta_r, be carful that the inner and outer bondary of the integration domain is smaller / larger than the inner / outer limit of the belt (i.e. a_in < KB_a0 - KB_delta_r and  KB_a0 + KB_delta_r < a_out).
- `KB_K`: np.float64 &rarr; The thermal diffusivity in Kuiper Belt's object (dimension: $[L]^2 . [T]^{-1}$)
- `KB_Phi`: np.float64 &rarr; The KBO's porosity (no dimensions)
- `KB_rp`:  np.float64 &rarr; The pore's radius for KBO
- `KB_f_ice`: np.float64 &rarr; The ice to refractory mass ratio for KBO (no dimensions)
- `KB_rho_refr`: np.float64 &rarr; The density of refractory materials for KBOs (dimension: $[M] . [L]{-3}$)
- `KB_rho_ice`: np.float64 &rarr; The density of CO ice for KBOs (dimension: $[M] . [L]{-3}$)
- `KB_sublimation_model`: str &rarr; The sublimation model, can be `none`, `constant_rate`, `thermal_diffusion` or `thermal_full`
- `KB_const_mdot`: np.float64 &rarr; The mass generation rate for the`constant_rate` sublimation level
- `KB_SD_amax`: np.float64 &rarr; The sizes used for the size distribution of kuiper belt (maximum size)
- `KB_SD_abig`: np.float64 &rarr; The sizes used for the size distribution of kuiper belt 
- `KB_SD_amed`: np.float64 &rarr; The sizes used for the size distribution of kuiper belt 
- `KB_SD_amin`: np.float64 &rarr; The sizes used for the size distribution of kuiper belt (minimum size)
- `KB_SD_qh`: np.float64 &rarr; The power slope of size distribution between `AB_SD_amax` and `AB_SD_big`
- `KB_SD_qm`: np.float64 &rarr; The power slope of size distribution between `AB_SD_big` and `AB_SD_med`

- `KB_sb`:

- `KB_t1_diss`: np.float64 &rarr; Kuiper belt disruption timescale

- `a_planets`: np.array[np.float64] &rarr; Array of planet's semi-major axis (one dimensional array)
- `m_planets`: np.array[np.float64] &rarr; Array of planet's masses (one dimensional array, be sure that it have the same size of `a_planets`)
- `f_accr`: np.float64 &rarr; The planet's accretion efficiency (no dimension)
- `t0`: np.float64 &rarr; The protoplanetary disc lifetime

- `IT_s`: int &rarr; The number of spatial steps
- `dip`: int &rarr; half of the number of sink cells around a planet
- `rtol`: np.float64 &rarr; The relative tolerance for time integration (see [scipy.integrate.solve_ivp](https://docs.scipy.org/doc/scipy/reference/generated/scipy.integrate.solve_ivp.html) documentation)
- `atol`: np.float64 &rarr; The absolute tolerance for time integration (see [scipy.integrate.solve_ivp](https://docs.scipy.org/doc/scipy/reference/generated/scipy.integrate.solve_ivp.html) documentation)

## Default unit system

It works with its own unit system, which is fully described by the conversion factor from the universal MKSA system.
Only the temperature unit is set to Kelvin and cannot be modified.
There are then three main conversion factors, `C_L`, `C_M` and `C_t` to convert any length, mass or time from metres, kilograms and seconds to the code's length, mass or time units. Multiply the value by the correct conversion factor to make the conversion.
To simplify operations, there are derived conversion factor units, such as  `C_F` `C_rho` `C_E` and `C_Lum` to convert force, density, energy or luminosity from the MKSA system to the code unit system.

The default values are:
- For the time : one code unit is equal to one million years (hence $C_L = 1 / (3600 * 24 * 365.25 * 1e6)$.)
- For the mass : one code unit is equal to one earth mass (hecne $C_L = 1 / M_\oplus$)
- For the lenght : one code unit is equal to one astronomical unit

To convert code values into MKSA units, divide them by the relevant conversion facteur unit.

Example:

```
mass_mksa = masse / C_M
lenght_mksa = length / C_L
time_mksa = time / C_t
surface_density_mksa = surface_density * C_L * C_L * C_L / C_M 
```

Typical constants can also be used for unit conversion. For example, the constants `yr`, `kyr`, `Myr` or `Gyr` can be used to convert times into years, kiloyears, megayears or gigayears.
It is also possible to convert mass into solar mass by dividing the mass by one solar mass.

The default values were chosen to fit the typical values for our models. However, it is also possible to modify them if needed.
Since the 'Sol' objects keep their own conversion factors, they can be loaded with the system of units that was used to integrate them. All conversions will be made automatically.

To do so, a new dictionary of constants must be built and saved into the working directory or the 'racine' directory with the name 'constantes'
using [np.saved_compressed](https://numpy.org/doc/stable/reference/generated/numpy.savez_compressed.html) method :

## The luminosity file

The central star's luminosity is a key parameter for estimating the mass generation rate at the belt level in the 'thermal_full' model.
It is also important for estimating the photodissociation rate.
However, the central star's luminosity can vary significantly in the early stages of a system's life, when secondary gas production is assumed to occur (see [kral et al 2024](https://ui.adsabs.harvard.edu/abs/2024A%26A...692A..70K/abstract) for the solar system and Figure 1)

------------------------------------------------------------------------------------------------------------------------

![luminosity](stars_luminosity.png)

_Figure 1 : Evolution of stellar luminosity as function of time for different star's mass_

------------------------------------------------------------------------------------------------------------------------

To provide the requested data, one must first run stellar simulation (for example, using [cesam2k20](https://www.ias.u-psud.fr/cesam2k20/)).
These simulations must be done for several masses (as much as possible to get reliable interpolation). 

All the data should then be merged into a single `.npz` created by [np.saved_compressed](https://numpy.org/doc/stable/reference/generated/numpy.savez_compressed.html).

This table must contain the following keys associated with arrays of the same sizes:

- `Age` : This array contains the star's age in Myr at each point
- `M` : The star's mass in sun's mass (must be counstant for each star) at each point
- `Lbol` : The bolometric luminosity at each point in solar luminosity
- `R` : The star's radius in solar radius at each point
- `Reuv_3692` : The luminosity fraction in the UV
- `Reuv_lya` : The luminosity fraction in the UV
